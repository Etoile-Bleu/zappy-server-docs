Zappy Server

Incantation

Source: server/src/utils/actions/incantation/, server/src/utils/commands/handle_ai_command.rs

Incantation is the elevation ritual. A group of players of the same level on the same tile can collectively raise their level by consuming specific stones. The ritual takes 300 time units (300/f seconds).

Two-phase design

Incantation uses a two-phase commit: preconditions are verified immediately at queue time (Phase 1), and the ritual executes after the 300-tick countdown (Phase 2). This prevents a player from queuing an incantation that had no chance of succeeding.

Sequence

sequenceDiagram
    participant AI as Initiator AI
    participant Server
    participant Participants
    participant GUI

    AI->>Server: Incantation

    Note over Server: Phase 1 — at queue time

    Server->>Server: collect_participants(world, x, y, level)
    Server->>Server: requirements_for(level)
    alt not enough players OR not enough resources
        Server->>AI: ko
    else preconditions met
        Server->>Server: enqueue Incantation action (300 ticks)
        Server->>Server: store ActiveIncantation { initiator, participants }
        loop for each participant
            Server->>Participants: "Elevation underway\n"
            Server->>Server: player.frozen = true
        end
        Server->>GUI: pic X Y L #p1 #p2 ...
    end

    Note over Server: Phase 2 — 300 ticks later

    Server->>Server: re-check participants still on tile, same level
    Server->>Server: re-check resources still present

    alt still valid
        Server->>Server: consume resources from tile
        loop for each participant
            Server->>Server: player.level += 1
            Server->>Server: player.frozen = false
            Server->>Participants: "Current level: N\n"
            Server->>GUI: plv #n new_level
        end
        Server->>GUI: pie X Y 1 (success)
        Server->>Server: check_victory()
    else conditions no longer met
        loop for each participant
            Server->>Participants: ko
            Server->>Server: player.frozen = false
        end
        Server->>GUI: pie X Y 0 (failure)
    end

requirements_for(level: u8) -> Option<LevelRequirement> returns None for level 0 or level >= 8, making it impossible to incant at max level.

Participant collection

#![allow(unused)]
fn main() {
pub(crate) fn collect_participants(
    world: &World,
    x: u32,
    y: u32,
    level: u8,
) -> Vec<PlayerId> {
    world.map.get(x, y).players.iter()
        .filter(|&&pid| {
            world.players.get(&pid)
                .is_some_and(|p| p.level == level && !p.frozen)
        })
        .copied()
        .collect()
}
}

Only players on the same tile, at the same level as the initiator, and not already frozen in another incantation qualify. The initiating player is always included (they are on the tile and not yet frozen at collection time).

ActiveIncantation

Between Phase 1 and Phase 2 the world stores which participants were locked in:

#![allow(unused)]
fn main() {
pub struct ActiveIncantation {
    pub initiator: PlayerId,
    pub participants: Vec<PlayerId>,
}
}

World.active_incantations: Vec<ActiveIncantation> holds one entry per in-flight ritual. At Phase 2 fire time, incantation/mod.rs removes the matching entry by initiator and re-verifies each participant's position, level, and frozen state against the tile's current resources.

Resource consumption

tile.resources.consume(&req.resources) subtracts all required stones in one call after has_enough confirms they are present. This is an atomic operation: if has_enough returns true, consume will not panic.

Freeze flag

player.frozen is set to true at Phase 1 (queue time), immediately after conditions are confirmed and pic is broadcast. This prevents participants from executing new actions while the ritual is counting down.

A frozen player can still receive commands — they are buffered in the action queue — but tick_action will not fire any action while frozen == true. On ritual completion (success or failure), all participants are unfrozen and their queued actions resume normally.
