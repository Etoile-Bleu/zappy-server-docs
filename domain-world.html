Zappy Server

World and Time System

Source: server/src/world/world.rs

World is the aggregate root of the domain layer. It owns all mutable game state and exposes a single tick method that drives the entire simulation.

Structure

#![allow(unused)]
fn main() {
pub struct World {
    pub map: Map,
    pub teams: Vec<Team>,
    pub players: HashMap<PlayerId, Player>,
    pub eggs: HashMap<EggId, Egg>,
    pub active_incantations: Vec<ActiveIncantation>,
    pub tick: u64,
    pub freq: u32,
    // private: spawner, next_player_id, next_egg_id
}

pub struct ActiveIncantation {
    pub initiator: PlayerId,
    pub participants: Vec<PlayerId>,
}
}

active_incantations tracks in-flight incantation rituals between Phase 1 (queue time) and Phase 2 (fire time). See Incantation for the full two-phase design.

players and eggs use HashMap for O(1) lookup by id. teams uses Vec because team lookup is always by name scan over a small slice (typically 2-8 teams).

The tick loop

sequenceDiagram
    participant App as app.rs
    participant World
    participant Player
    participant Spawner as ResourceSpawner

    App->>+World: advance_tick()
    World->>World: tick += 1
    loop for each player
        World->>Player: tick_food()
        alt food exhausted
            World->>World: remove player from map + players
            World-->>App: WorldEvent::PlayerStarved
        end
    end
    loop for each surviving player
        World->>Player: tick_action()
        alt timer reached zero
            World-->>App: WorldEvent::ActionReady { action }
        end
    end
    alt tick % 20 == 0
        World->>Spawner: respawn(&mut map)
        World-->>App: WorldEvent::TilesUpdated { positions }
    end
    World-->>-App: Vec<WorldEvent>

WorldEvent

#![allow(unused)]
fn main() {
pub enum WorldEvent {
    PlayerStarved { player_id: PlayerId },
    ActionReady { player_id: PlayerId, action: Action },
    TilesUpdated { positions: Vec<(u32, u32)> },
}
}

advance_tick returns events as plain data. The World has no knowledge of networking. It is the caller (app.rs) that sends dead\n to a starved AI client, broadcasts pdi to GUI clients, and executes the game logic for a fired action.

This design follows the event-driven architecture principle at the domain level: the world announces what happened; the application layer decides what to do about it.

Reference: Event-driven architecture -- Martin Fowler

Design patterns

Single mutable owner

All game state lives in World. There is no shared ownership (Arc, Mutex), no channels, no background threads. The event loop holds one World value and mutates it by calling advance_tick once per time unit.

This approach eliminates an entire class of concurrency bugs. A Rust &mut World is an exclusive mutable reference; the borrow checker guarantees no other code can read or write world state while advance_tick runs.

Action timer colocation

Each Player holds its own action_ticks_remaining: u32. The alternative (a HashMap<PlayerId, u32> on World) would require two structures to stay in sync whenever a player is removed.

Keeping the timer on the player makes removal trivial: removing the player from world.players deletes the timer automatically.

Respawn determinism

#![allow(unused)]
fn main() {
if self.tick % RESPAWN_PERIOD == 0 { ... }   // fires at 20, 40, 60, ...
}

Respawn fires at absolute multiples of 20, not 20 ticks after the last fire. If the server catches up after a stall, multiple missed respawns execute sequentially but at the correct tick numbers. Behavior is deterministic and independent of wall-clock time.

Initial slot model

World::new calls Team::new(name, 0) and then team.add_egg(id) once per client slot. This ensures available_slots always equals the number of eggs on the map. Every connection goes through the remove_egg path, which handles both slot accounting and egg position lookup in one operation.

SpawnedPlayer

spawn_player_from_team_egg returns a SpawnedPlayer on success:

#![allow(unused)]
fn main() {
pub struct SpawnedPlayer {
    pub player_id: PlayerId,
    pub egg_id: EggId,
    pub x: u32,
    pub y: u32,
    pub remaining_slots: u32,
}
}

egg_id is the id of the egg that was consumed. The handshake layer uses it to broadcast ebo #egg_id to GUI clients immediately after pnw.

Time system

The server operates in time units. One time unit = 1 / freq seconds. The reactor calls advance_tick once per time unit.

Spec requirementImplementation
Global tick counter at rate f/sworld.tick incremented in advance_tick
Action execution time = cost / fenqueue_action sets ticks = action.time_cost()
Per-player action timerplayer.action_ticks_remaining decremented in tick_action
Food decrement: 1 unit per 126 time unitstick_food decrements food_ticks_remaining
Resource respawn every 20 time unitstick % RESPAWN_PERIOD == 0

Rule: never use wall-clock seconds inside the domain layer. If a caller needs seconds, it divides by freq at the boundary.
