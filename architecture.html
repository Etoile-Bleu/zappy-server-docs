Zappy Server

Architecture overview

The server is organized into four layers. Each layer has a strict dependency rule: it may only import from layers below it, never above.

Hexagonal architecture

The server follows the Ports and Adapters pattern introduced by Alistair Cockburn in 2005. The central idea: the domain should be independent of the delivery mechanism. Whether the outside world communicates through TCP, a test harness, or a future RPC layer, the World struct and its invariants remain unchanged.

Ports are the boundary interfaces:

  • Inbound: NetworkEvent (raw bytes from clients), WorldEvent (timer expiry, starvation)
  • Outbound: GuiNotification (serialized and pushed to GUI clients)

Adapters translate between ports and the domain:

  • protocol::ai and protocol::gui parse raw bytes into typed commands
  • protocol::gui::format serializes typed notifications into wire strings
  • utils/actions/ maps typed commands to domain mutations

The critical rule: world/ imports nothing from protocol/ or network/. The wire encoding for Direction::North (integer 1) lives exclusively in protocol::gui::format::player::orientation_code. The domain type carries no protocol knowledge.

References:

  • Hexagonal Architecture -- Alistair Cockburn (2005)
  • Ports and Adapters -- Herberto Graca (2017)

Functional core, imperative shell

Gary Bernhardt's 2012 pattern structures code around two distinct zones:

  • Functional core: pure functions with no side effects. All parsers (protocol::ai::parse, protocol::gui::parse, protocol::gui::format) live here. Given an input, they return an output. No sockets, no state, no mutable globals.
  • Imperative shell: code that manages side effects. The reactor, app.rs, and utils/actions/ live here. They mutate world state, write to sockets, and schedule ticks.

This split makes the functional core trivially testable (no mocks, no setup, no teardown) and the imperative shell clearly bounded in scope.

References:

  • Functional Core, Imperative Shell -- Gary Bernhardt (2012)
  • Functional Core / Imperative Shell -- Medium
