Toroidal Map

Source: server/src/world/map.rs

Map is a 2D toroidal grid of tiles. Every coordinate access wraps automatically; there are no bounds checks that can fail at runtime.

Flat buffer layout

The map is stored as a single contiguous Vec<Tile> in row-major order:

index = y * width + x

graph LR
    subgraph "Vec<Tile> in memory"
        T00["(0,0)"] --- T10["(1,0)"] --- T20["(2,0)"] --- T01["(0,1)"] --- T11["(1,1)"] --- T21["(2,1)"]
    end

The alternative, Vec<Vec<Tile>>, requires one heap allocation per row and one pointer dereference per row access. The flat layout has a single allocation and exploits spatial locality: tiles on the same row are adjacent in memory, making sequential access cache-friendly.

  • Row- and column-major order -- Wikipedia

Single point of truth for indexing

All coordinate-to-index arithmetic lives in one private method:

#![allow(unused)]
fn main() {
fn flat_index(&self, x: u32, y: u32) -> usize {
    (y as usize) * (self.width as usize) + (x as usize)
}
}

get, get_mut, Index, and IndexMut all delegate to flat_index. If the formula ever needs to change, there is exactly one place to edit and one place to test.

Reference: Single source of truth -- Wikipedia

Toroidal arithmetic

Movement uses signed deltas applied to unsigned coordinates. Naive subtraction underflows; a single % returns negative values in Rust. The solution uses i64 intermediates and rem_euclid:

#![allow(unused)]
fn main() {
pub fn offset(&self, x: u32, y: u32, dx: i32, dy: i32) -> (u32, u32) {
    let nx = ((x as i64 + dx as i64).rem_euclid(self.width as i64)) as u32;
    let ny = ((y as i64 + dy as i64).rem_euclid(self.height as i64)) as u32;
    (nx, ny)
}
}

rem_euclid always returns a non-negative value, so wrapping past the left or top edge works correctly:

(-1).rem_euclid(10) == 9   // wraps to the right edge
(-1) % 10           == -1  // wrong for toroidal semantics

API

Map::new(width, height)           -> Map       create empty grid
Map::get(&self, x, y)             -> &Tile     toroidal read
Map::get_mut(&mut self, x, y)     -> &mut Tile toroidal write
Map::offset(&self, x, y, dx, dy) -> (u32,u32)  toroidal step
Map::width(&self)                 -> u32
Map::height(&self)                -> u32
Map::tile_count(&self)            -> usize
map[(x, y)]                                    Index / IndexMut traits

All coordinate inputs wrap automatically. There are no panics for out-of-bounds coordinates.

Operator overloading

Map implements std::ops::Index<(u32, u32)> and IndexMut<(u32, u32)>:

#![allow(unused)]
fn main() {
let food = map[(2, 3)].resources.food;
map[(2, 3)].resources.add(ResourceKind::Food, 1);
}

The trait implementations are thin wrappers over get and get_mut. Using standard library traits makes Map consistent with Rust's collection idioms.

Reference: std::ops::Index -- Rust Standard Library
