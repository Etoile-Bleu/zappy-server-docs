Tiles and Resources

Sources: server/src/world/resource.rs, server/src/world/tile.rs, server/src/world/resource_spawner.rs

Resource kinds

#![allow(unused)]
fn main() {
#[derive(Debug, Clone, Copy, PartialEq)]
pub enum ResourceKind {
    Food, Linemate, Deraumere, Sibur, Mendiane, Phiras, Thystame,
}
}

Copy is derived because the enum has no heap-allocated fields; passing by value is cheaper than passing a reference for a 1-byte type.

ResourceKind was originally defined in the protocol layer alongside its wire index encoding. It was moved to world/resource.rs so that the dependency direction is correct: the protocol layer imports from the domain, never the other way around.

Resources struct

#![allow(unused)]
fn main() {
#[derive(Debug, Default, Clone, PartialEq)]
pub struct Resources {
    pub food: u32,
    pub linemate: u32,
    pub deraumere: u32,
    pub sibur: u32,
    pub mendiane: u32,
    pub phiras: u32,
    pub thystame: u32,
}
}

Resources is used both for tile contents (what lies on the ground) and player inventories (what a drone carries). Default yields all-zero, the correct starting state for an empty tile or newly spawned player.

Methods

MethodSignaturePurpose
get(&self, kind) -> u32Read one field
add(&mut self, kind, amount)Increment one field
take(&mut self, kind, amount) -> Result<(), TileError>Decrement; error if insufficient
has_enough(&self, required: &Resources) -> boolCheck all fields
consume(&mut self, other: &Resources)Subtract all fields (precondition: has_enough)

Atomic take

take is atomic: if the available quantity is less than amount, the field is not modified and the error carries the context needed to log or respond without a second lookup:

#![allow(unused)]
fn main() {
pub enum TileError {
    InsufficientResource { kind: ResourceKind, available: u32, needed: u32 },
}
}

This is the domain-layer application of Parse, Don't Validate: the caller receives a value that explains the failure, not a boolean that forces another check.

Preconditioned consume

consume subtracts field-by-field without checking. It is designed to be called after has_enough has confirmed validity:

#![allow(unused)]
fn main() {
// End-of-incantation sequence:
if tile.resources.has_enough(&required) {
    tile.resources.consume(&required);  // safe: has_enough already confirmed
}
}

Rust's debug builds catch arithmetic underflow as a panic, making misuse immediately visible during development.

Tile

#![allow(unused)]
fn main() {
#[derive(Debug, Default)]
pub struct Tile {
    pub resources: Resources,
    pub players: Vec<u32>,  // player ids standing here
}
}

Multiple players may share a tile; the spec states Trantorians "easily run into their fellow creatures." Default yields an empty tile.

Respawn via deficit calculation

respawn counts the current total of each type in a single pass over all tiles, computes the deficit, and places only the missing units:

flowchart LR
    A["Count all resources<br/>on map"] --> B["Compute deficit<br/>= target - current"]
    B --> C{deficit > 0?}
    C -->|yes| D["Place deficit<br/>units randomly"]
    C -->|no| E["No-op"]
    D --> F["Return changed<br/>tile positions"]

This design is idempotent: calling respawn twice when the map is full changes nothing and returns an empty list. The total cost scales with the deficit, not the full target.

Linear congruential generator

Rng uses the Knuth MMIX LCG constants (multiplier 6364136223846793005, addend 1442695040888963407) with u64 wrapping arithmetic. Two generators with the same seed produce identical sequences, making game runs reproducible.

The upper 32 bits of each step are used for next_below to exploit the better statistical properties of the high bits in an LCG (low bits in a standard LCG have shorter periods).

References:

  • Linear congruential generator -- Wikipedia
  • Knuth, The Art of Computer Programming Vol. 2, section 3.3.4

Domain service: take_resource / drop_resource

take_resource and drop_resource each operate on both a Tile and a Player. Placing this logic on either type would create an import in the wrong direction. Free functions are the correct choice for operations that "do not naturally produce or act on a single type":

#![allow(unused)]
fn main() {
take_resource(&mut tile, &mut player, kind)?;  // tile -> player
drop_resource(&mut tile, &mut player, kind)?;  // player -> tile
}

Both delegate to Resources::take and Resources::add, preserving atomicity on failure.
