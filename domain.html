Zappy Server

Domain layer overview

The domain layer is the heart of the server. It owns all game state and enforces all game rules. It has no knowledge of sockets, wire formats, or protocol encodings.

Dependency Direction

protocol/ --> world/       (parsers and serializers import domain types)
world/    -/-> protocol/   (domain never imports protocol or network)

The Direction enum is defined in world/player/direction.rs. Its wire encoding (North=1, East=2, South=3, West=4) lives exclusively in protocol/gui/format/player.rs::orientation_code. The domain type is unaware of this encoding.

This dependency inversion is the central guarantee of hexagonal architecture: the domain can be tested, reasoned about, and evolved without touching infrastructure code.

Reference: Dependency Inversion Principle -- Wikipedia

DDD Vocabulary

The domain design follows Eric Evans' Domain-Driven Design classification:

CategoryTypeReason
Aggregate RootWorldAll game state accessed through one owner
EntityPlayerHas unique identity (PlayerId), mutable state
Value ObjectDirectionNo identity, immutable, equality by value
Value ObjectResourcesNo identity, all fields comparable
Value ObjectEggPosition + team; identity tracked by EggId, not in-place mutation
NewtypePlayerId, EggId, TokenDistinct types prevent accidental mixing
Domain Servicetake_resource, drop_resourceOperations on two types simultaneously
Repositoryworld.players: HashMap<PlayerId, Player>Lookup by identity
