Protocol layer overview

The protocol layer translates between raw TCP bytes and typed Rust values. It has two halves that are deliberately symmetric and independent:

graph LR
    subgraph "Inbound (parsing)"
        AI_RAW["'Forward\n'"] --> AIP["protocol::ai::parse()"]
        AIP --> AIT["AiCommand::Forward"]
        GUI_RAW["'bct 3 7\n'"] --> GUIP["protocol::gui::parse()"]
        GUIP --> GUIT["GuiCommand::Bct { x: 3, y: 7 }"]
    end

    subgraph "Outbound (serializing)"
        NOT["GuiNotification::PlayerPosition { ... }"] --> FMT["protocol::gui::format()"]
        FMT --> STR["'ppo #1 3 7 2\n'"]
    end

All three functions are pure functions: given an input, they return an output, mutate nothing, and cause no side effects. This makes them trivially testable and impossible to misuse.

Shared design principles

Parse, Don't Validate

Coined by Alexis King in 2019, this principle states: instead of passing raw input alongside a trust assumption, parse it once into a type that makes invalid states unrepresentable.

Applied throughout this layer: neither app.rs nor any action handler ever sees a raw &str. Every value that crosses the parse boundary is either a typed AiCommand / GuiCommand, or a typed error. The caller cannot accidentally treat a tile Y-coordinate as a player id.

Reference: Parse, don't validate -- Alexis King (2019)

Newtype pattern

PlayerId(u32) and EggId(u32) are newtypes: single-field structs that give a u32 a distinct type identity. The compiler rejects passing one where the other is expected, at zero runtime cost.

References:

  • New Type Idiom -- Rust By Example
  • Newtype -- Rust Design Patterns
  • Item 6: Embrace the newtype pattern -- Effective Rust

Exhaustive pattern matching

Rust's match on an enum must cover every variant. Adding a new GuiNotification variant without updating format() is a compile error, not a runtime surprise. This compiler-enforced completeness eliminates an entire category of protocol bugs.

Reference: Pattern and exhaustiveness checking -- Rust Compiler Development Guide
