GUI Commands

Source: server/src/protocol/gui/

The GUI command parser turns raw observer requests into typed GuiCommand values. Like the AI parser, it is a pure transformer: no I/O, no state mutation, no side effects.

File structure

server/src/protocol/gui/
    mod.rs        public re-exports
    error.rs      ParseError enum
    command.rs    GuiCommand enum
    lexer.rs      Tokens struct (zero-copy cursor)
    parse.rs      parse() entry point

Parsing a player ID

Player IDs on the wire are prefixed with #: ppo #3 means player 3. Tokens::next_player_id strips the # prefix with strip_prefix, then parses the remaining digits into a u32 wrapped in PlayerId. The # prefix is the wire format concern; the domain type PlayerId(u32) carries no #.

flowchart LR
    RAW["'ppo #3'"] --> CMD["next_str() = ppo"]
    CMD --> PID["next_player_id()"]
    PID --> STRIP["strip_prefix('#') = 3"]
    STRIP --> PARSE["parse u32 = 3"]
    PARSE --> WRAP["PlayerId(3)"]
    WRAP --> OK["Ok(Ppo { player_id: PlayerId(3) })"]

Separation of lexing and parsing

Two stages are kept deliberately separate:

  • Lexing (lexer.rs): converts &str into a stream of typed tokens via a zero-copy cursor. No heap allocation on the happy path.
  • Parsing (parse.rs): converts the token stream into a GuiCommand. The command name is the sole lookahead token.

Adding a new command requires only two changes: a new variant in GuiCommand and a new match arm in parse(). The lexer never changes for new commands.

Error variants

VariantCause
UnknownCommand(Box<str>)Command name not in the protocol
MissingArgumentInput ended before all required tokens were consumed
InvalidNumberA u32 token could not be parsed
InvalidPlayerIdFormatA player id token lacked the # prefix or had non-digit digits
TrailingInputUnconsumed non-whitespace content after all expected arguments

TrailingInput is checked by calling tokens.expect_end() as the last step in every match arm. This rejects inputs like msz extragarbage that would otherwise silently succeed.
