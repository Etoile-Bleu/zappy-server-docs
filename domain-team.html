Zappy Server

Team and Egg

Sources: server/src/world/team.rs, server/src/world/egg.rs

Slot model

The spec defines a per-team connection counter. Team enforces it with private fields and behavioral methods:

EventOperationEffect on available_slots
Server startsTeam::new(name, 0) then add_egg x N+= N
Player executes Forkteam.add_egg(id)+= 1
New client connectsteam.remove_egg(egg_id) (via spawn_player_from_team_egg)-= 1
Egg ejected from tileteam.remove_egg(id)-= 1
#![allow(unused)]
fn main() {
pub struct Team {
    pub name: String,
    available_slots: u32,   // private
    eggs: Vec<EggId>,       // private
}
}

There is no set_available_slots method. Creating an inconsistent state from outside the module is impossible.

Egg as value object

#![allow(unused)]
fn main() {
#[derive(Debug, Clone, PartialEq)]
pub struct Egg {
    pub id: EggId,
    pub team: String,
    pub x: u32,
    pub y: u32,
}
}

Egg has no mutable methods. When an egg changes status (hatches or is destroyed), the caller removes it from the world and from the team. There is no in-place mutation of an existing egg.

This is the Value Object pattern from DDD: the egg is not defined by continuity of identity but by its attributes. EggId is the identifier; the egg itself is disposable data.

Reference: Evans Classification -- Martin Fowler

Why Team and Egg are separate types

Team stores only EggIds, not full Egg values. Position and team name live in Egg, which the World owns alongside Player. The link is the id:

Tile::players   Vec<PlayerId> --> Player in World.players
Team::eggs      Vec<EggId>    --> Egg    in World.eggs

Storing full Egg values inside Team would couple access policy (slot count) with physical location (tile position). Those two concerns change independently.

Encapsulation by invariant

available_slots and eggs are private. The public methods maintain the invariant atomically:

  • add_egg: records the egg id and increments available_slots.
  • remove_egg: removes the id and decrements available_slots with saturating_sub (never goes below zero).
  • consume_slot: decrements available_slots by one but returns Err(NoSlotsAvailable) before decrementing if already at zero.

There is no path that leaves the counter inconsistent with the egg list.
