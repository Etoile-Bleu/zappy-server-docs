Zappy Serveur

Incantation

Sources : server/src/utils/actions/incantation/, server/src/utils/commands/handle_ai_command.rs

L'incantation est le rituel d'élévation. Un groupe de joueurs du même niveau sur la même tuile peut collectivement augmenter son niveau en consommant des pierres spécifiques. Le rituel prend 300 unités de temps (300/f secondes).

Conception en deux phases

L'incantation utilise un commit en deux phases : les préconditions sont vérifiées immédiatement au moment de la mise en file (Phase 1), et le rituel s'exécute après le décompte de 300 ticks (Phase 2). Cela empêche un joueur de mettre en file une incantation qui n'aurait aucune chance de réussir.

Séquence

sequenceDiagram
    participant AI as IA Initiatrice
    participant Server as Serveur
    participant Participants
    participant GUI

    AI->>Server: Incantation

    Note over Server: Phase 1 - au moment de la mise en file

    Server->>Server: collect_participants(world, x, y, level)
    Server->>Server: requirements_for(level)
    alt pas assez de joueurs OU pas assez de ressources
        Server->>AI: ko
    else préconditions remplies
        Server->>Server: mettre Incantation en file (300 ticks)
        Server->>Server: stocker ActiveIncantation { initiator, participants }
        loop pour chaque participant
            Server->>Participants: "Elevation underway\n"
            Server->>Server: player.frozen = true
        end
        Server->>GUI: pic X Y L #p1 #p2 ...
    end

    Note over Server: Phase 2 - 300 ticks plus tard

    Server->>Server: revérifier que les participants sont sur la tuile, même niveau
    Server->>Server: revérifier que les ressources sont toujours présentes

    alt toujours valide
        Server->>Server: consommer les ressources de la tuile
        loop pour chaque participant
            Server->>Server: player.level += 1
            Server->>Server: player.frozen = false
            Server->>Participants: "Current level: N\n"
            Server->>GUI: plv #n nouveau_niveau
        end
        Server->>GUI: pie X Y 1 (succès)
        Server->>Server: check_victory()
    else conditions plus remplies
        loop pour chaque participant
            Server->>Participants: ko
            Server->>Server: player.frozen = false
        end
        Server->>GUI: pie X Y 0 (échec)
    end

requirements_for(level: u8) -> Option<LevelRequirement> retourne None pour le niveau 0 ou level >= 8, rendant impossible d'incanter au niveau maximum.

Collecte des participants

#![allow(unused)]
fn main() {
pub(crate) fn collect_participants(
    world: &World,
    x: u32,
    y: u32,
    level: u8,
) -> Vec<PlayerId> {
    world.map.get(x, y).players.iter()
        .filter(|&&pid| {
            world.players.get(&pid)
                .is_some_and(|p| p.level == level && !p.frozen)
        })
        .copied()
        .collect()
}
}

Seuls les joueurs sur la même tuile, au même niveau que l'initiateur, et pas déjà gelés dans une autre incantation sont éligibles. Le joueur initiant est toujours inclus (il est sur la tuile et pas encore gelé au moment de la collecte).

ActiveIncantation

Entre la Phase 1 et la Phase 2, le monde stocke quels participants ont été verrouillés :

#![allow(unused)]
fn main() {
pub struct ActiveIncantation {
    pub initiator: PlayerId,
    pub participants: Vec<PlayerId>,
}
}

World.active_incantations: Vec<ActiveIncantation> contient une entrée par rituel en cours. Au moment du déclenchement de la Phase 2, incantation/mod.rs supprime l'entrée correspondante par initiator et revérifie la position, le niveau et l'état gelé de chaque participant par rapport aux ressources actuelles de la tuile.

Consommation des ressources

tile.resources.consume(&req.resources) soustrait toutes les pierres requises en un seul appel après que has_enough confirme leur présence. C'est une opération atomique : si has_enough retourne vrai, consume ne paniquera pas.

Drapeau de gel

player.frozen est fixé à true lors de la Phase 1 (moment de la mise en file), immédiatement après la confirmation des conditions et la diffusion de pic. Cela empêche les participants d'exécuter de nouvelles actions pendant le décompte du rituel.

Un joueur gelé peut toujours recevoir des commandes - elles sont tamponnées dans la file d'actions - mais tick_action n'exécute aucune action tant que frozen == true. À la fin du rituel (succès ou échec), tous les participants sont dégelés et leurs actions en file reprennent normalement.
