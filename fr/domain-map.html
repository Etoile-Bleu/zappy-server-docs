Carte toroïdale

Source : server/src/world/map.rs

Map est une grille 2D toroïdale de tuiles. Tout accès par coordonnées enveloppe automatiquement ; il n'existe aucune vérification de bornes pouvant échouer à l'exécution.

Disposition en tampon plat

La carte est stockée en tant que Vec<Tile> contigu unique en ordre ligne-major :

index = y * largeur + x

graph LR
    subgraph "Vec<Tile> en mémoire"
        T00["(0,0)"] --- T10["(1,0)"] --- T20["(2,0)"] --- T01["(0,1)"] --- T11["(1,1)"] --- T21["(2,1)"]
    end

L'alternative, Vec<Vec<Tile>>, nécessite une allocation tas par ligne et une déréférence de pointeur par accès de ligne. La disposition plate n'a qu'une seule allocation et exploite la localité spatiale : les tuiles d'une même ligne sont adjacentes en mémoire, rendant l'accès séquentiel favorable au cache.

Source unique de vérité pour l'indexation

Toute l'arithmétique coordonnée-vers-index réside dans une méthode privée :

#![allow(unused)]
fn main() {
fn flat_index(&self, x: u32, y: u32) -> usize {
    (y as usize) * (self.width as usize) + (x as usize)
}
}

get, get_mut, Index et IndexMut délèguent tous à flat_index. Si la formule doit changer un jour, il y a exactement un endroit à modifier et un endroit à tester.

Référence : Single source of truth - Wikipedia

Arithmétique toroïdale

Le déplacement utilise des deltas signés appliqués à des coordonnées non signées. La soustraction naïve déborde ; un seul % retourne des valeurs négatives en Rust. La solution utilise des intermédiaires i64 et rem_euclid :

#![allow(unused)]
fn main() {
pub fn offset(&self, x: u32, y: u32, dx: i32, dy: i32) -> (u32, u32) {
    let nx = ((x as i64 + dx as i64).rem_euclid(self.width as i64)) as u32;
    let ny = ((y as i64 + dy as i64).rem_euclid(self.height as i64)) as u32;
    (nx, ny)
}
}

rem_euclid retourne toujours une valeur non négative, donc l'enveloppement au-delà du bord gauche ou supérieur fonctionne correctement :

(-1).rem_euclid(10) == 9   // enveloppe vers le bord droit
(-1) % 10           == -1  // incorrect pour la sémantique toroïdale

API

Map::new(largeur, hauteur)            -> Map       créer une grille vide
Map::get(&self, x, y)                 -> &Tile     lecture toroïdale
Map::get_mut(&mut self, x, y)         -> &mut Tile écriture toroïdale
Map::offset(&self, x, y, dx, dy)      -> (u32,u32) pas toroïdal
Map::width(&self)                     -> u32
Map::height(&self)                    -> u32
Map::tile_count(&self)                -> usize
map[(x, y)]                                        traits Index / IndexMut

Toutes les entrées de coordonnées s'enveloppent automatiquement. Il n'y a pas de panics pour des coordonnées hors limites.

Surcharge des opérateurs

Map implémente std::ops::Index<(u32, u32)> et IndexMut<(u32, u32)> :

#![allow(unused)]
fn main() {
let food = map[(2, 3)].resources.food;
map[(2, 3)].resources.add(ResourceKind::Food, 1);
}

Les implémentations des traits sont de fines couches au-dessus de get et get_mut. Utiliser les traits de la bibliothèque standard rend Map cohérente avec les idiomes de collections Rust.
