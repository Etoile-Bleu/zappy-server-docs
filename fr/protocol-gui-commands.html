Commandes GUI

Source : server/src/protocol/gui/

Le parseur de commandes GUI transforme les requêtes brutes des observateurs en valeurs GuiCommand typées. Comme le parseur IA, c'est un transformateur pur : pas d'E/S, pas de mutation d'état, pas d'effets de bord.

Structure des fichiers

server/src/protocol/gui/
    mod.rs        re-exports publics
    error.rs      enum ParseError
    command.rs    enum GuiCommand
    lexer.rs      struct Tokens (curseur zéro-copie)
    parse.rs      point d'entrée parse()

Parsage d'un identifiant de joueur

Les identifiants de joueur sur le réseau sont préfixés par # : ppo #3 désigne le joueur 3. Tokens::next_player_id retire le préfixe # avec strip_prefix, puis parse les chiffres restants en u32 encapsulé dans PlayerId. Le préfixe # est une préoccupation du format réseau ; le type domaine PlayerId(u32) ne porte pas de #.

flowchart LR
    RAW["'ppo #3'"] --> CMD["next_str() = ppo"]
    CMD --> PID["next_player_id()"]
    PID --> STRIP["strip_prefix('#') = 3"]
    STRIP --> PARSE["parse u32 = 3"]
    PARSE --> WRAP["PlayerId(3)"]
    WRAP --> OK["Ok(Ppo { player_id: PlayerId(3) })"]

Séparation du lexage et du parsage

Deux étapes sont maintenues délibérément séparées :

  • Lexage (lexer.rs) : convertit &str en un flux de tokens typés via un curseur zéro-copie. Pas d'allocation tas sur le chemin nominal.
  • Parsage (parse.rs) : convertit le flux de tokens en GuiCommand. Le nom de la commande est le seul token de lookahead.

Ajouter une nouvelle commande ne nécessite que deux changements : une nouvelle variante dans GuiCommand et un nouveau bras de match dans parse(). Le lexer ne change jamais pour de nouvelles commandes.

Variantes d'erreur

VarianteCause
UnknownCommand(Box<str>)Nom de commande absent du protocole
MissingArgumentL'entrée s'est terminée avant que tous les tokens requis soient consommés
InvalidNumberUn token u32 n'a pas pu être parsé
InvalidPlayerIdFormatUn token d'id de joueur manquait le préfixe # ou contenait des caractères non numériques
TrailingInputContenu non-espace après tous les arguments attendus

TrailingInput est vérifié en appelant tokens.expect_end() comme dernière étape dans chaque bras de match. Cela rejette des entrées comme msz extragarbageinvalid qui réussiraient sinon silencieusement.
